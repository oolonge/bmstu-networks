                    AS 65001 (OSPF)

## Основные понятия

### Типы протоколов маршрутизации

| Класс | Принцип работы | Примеры |
|-------|----------------|---------|
| **Distance-Vector** | Передаёт таблицу маршрутов соседям | RIPv2 |
| **Link-State** | Строит полную топологию сети | OSPF |
| **Path-Vector** | Передаёт путь через AS | BGP |

### Административное расстояние (AD)

Приоритет источника маршрута. **Меньше = лучше**.

| Источник | AD |
|----------|----:|
| Connected | 0 |
| Static | 1 |
| eBGP | 20 |
| EIGRP | 90 |
| OSPF | 110 |
| RIPv2 | 120 |
| iBGP | 200 |

**AD — локальная настройка роутера**, не передаётся между устройствами.

### Классовые vs бесклассовые протоколы

| Тип | Передаёт маску? | Поддержка VLSM | Примеры |
|-----|-----------------|----------------|---------|
| Классовый | ❌ | ❌ | RIPv1 |
| Бесклассовый | ✅ | ✅ | RIPv2, OSPF, EIGRP, BGP |

**VLSM** — использование разных масок в одной сети (/30 для линков, /24 для LAN).

## OSPF (Open Shortest Path First)

### Характеристики

- **Тип**: Link-State
- **AD**: 110
- **Метрика**: Cost = 100 Мбит/с ÷ bandwidth
- **Ограничение хопов**: Нет
- **Транспорт**: IP protocol 89, multicast 224.0.0.5

### Типы пакетов OSPF

| Тип | Название | Назначение |
|-----|----------|------------|
| 1 | Hello | Обнаружение и поддержание соседства |
| 2 | DBD | Описание базы данных (список LSA) |
| 3 | LSR | Запрос конкретных LSA |
| 4 | LSU | Передача LSA (информация о сетях) |
| 5 | LSAck | Подтверждение получения |

### Установление соседства

```
R1                              R2
 │                               │
 │ ─── Hello ─────────────────→ │  (Я 1.1.1.1, area 0)
 │ ←── Hello ─────────────────  │  (Я 2.2.2.2, вижу 1.1.1.1)
 │                               │  Состояние: 2-WAY
 │ ─── DBD ───────────────────→ │
 │ ←── DBD ───────────────────  │  Состояние: EXCHANGE
 │ ←── LSR ───────────────────  │  (Дай LSA про R3, R4)
 │ ─── LSU ───────────────────→ │  (Вот они)
 │ ←── LSAck ─────────────────  │  Состояние: FULL
```

### Таймеры

- **Hello Interval**: 10 сек (Ethernet)
- **Dead Interval**: 40 сек (4 × Hello)

### Wildcard-маска

**Инверсия обычной маски**. 0 = проверять, 1 = игнорировать.

| Маска | Wildcard | Что покрывает |
|-------|----------|---------------|
| /30 (255.255.255.252) | 0.0.0.3 | 4 адреса |
| /24 (255.255.255.0) | 0.0.0.255 | 256 адресов |
| /32 (255.255.255.255) | 0.0.0.0 | 1 адрес |

### Конфигурация OSPF

```cisco
router ospf 1                              ! Process ID (локальный)
 router-id 1.1.1.1                         ! Уникальный ID роутера
 log-adjacency-changes                     ! Логировать изменения соседства
 network 172.21.12.0 0.0.0.3 area 0       ! Включить OSPF на интерфейсах
 network 172.21.1.1 0.0.0.0 area 0        ! Loopback (точный адрес)
 redistribute bgp 65001 subnets            ! BGP → OSPF
```

**Команда `network`**: Включает OSPF на интерфейсах, IP которых попадает в диапазон.

## BGP (Border Gateway Protocol)

### Характеристики

- **Тип**: Path-Vector
- **AD**: eBGP = 20, iBGP = 200
- **Метрика**: AS_PATH length + атрибуты
- **Транспорт**: TCP порт 179
- **Назначение**: Маршрутизация между автономными системами

### Типы BGP

| Тип | Описание | AD |
|-----|----------|----:|
| **eBGP** | Между разными AS | 20 |
| **iBGP** | Внутри одной AS | 200 |

### Типы сообщений

| Тип | Название | Назначение |
|-----|----------|------------|
| 1 | OPEN | Установление сессии |
| 2 | UPDATE | Анонсы маршрутов (NLRI + атрибуты) |
| 3 | NOTIFICATION | Ошибки, закрытие сессии |
| 4 | KEEPALIVE | Поддержание сессии |

### Установление соседства

```
R1 (AS 65001)                    R5 (AS 65002)
 │                                     │
 │ ════ TCP 3-way handshake ═════════▶│
 │ ─── OPEN (AS 65001, ID 1.1.1.1) ──▶│
 │ ◀── OPEN (AS 65002, ID 5.5.5.5) ───│
 │ ─── KEEPALIVE ────────────────────▶│
 │ ◀── KEEPALIVE ─────────────────────│  Состояние: ESTABLISHED
 │ ─── UPDATE (172.21.0.0/16) ───────▶│
 │ ◀── UPDATE (172.22.10.0/24) ───────│
```

### Таймеры

- **Keepalive**: 60 сек
- **Hold Time**: 180 сек

### Конфигурация BGP

```cisco
router bgp 65001                           ! Номер AS (глобальный!)
 bgp router-id 1.1.1.1                     ! ID роутера
 bgp log-neighbor-changes                  ! Логировать изменения
 no synchronization                        ! Отключить устаревшую синхронизацию
 neighbor 10.0.0.2 remote-as 65002         ! Настройка соседа (eBGP)
 network 172.21.0.0                        ! Анонсировать сеть
 redistribute ospf 1                       ! OSPF → BGP
```

**Команда `network` в BGP**: Анонсирует сеть соседям (НЕ включает протокол на интерфейсах!).

## Перераспределение маршрутов (Redistribution)

### Зачем нужно

Связать две разные области маршрутизации (OSPF ↔ BGP).

### На R1 (граничный роутер)

```
       AS 65002                      AS 65001
         │                             │
    172.22.x.x                    172.21.x.x
         │                             │
         ▼ redistribute                ▼ redistribute
         │   bgp → ospf                │   ospf → bgp
         ▼                             ▼
    OSPF видит:                   BGP видит:
    O E2 172.22.10.0/24           B 172.21.100.0/24
```

### Команды

```cisco
router ospf 1
 redistribute bgp 65001 subnets    ! subnets — включить подсети

router bgp 65001
 redistribute ospf 1
```

## Суммирование маршрутов

### Что это

Объединение нескольких маршрутов в один (агрегация).

### Пример

```
До суммирования:          После суммирования:
172.21.1.0/24             172.21.0.0/22
172.21.2.0/24       →     (1 маршрут вместо 4)
172.21.3.0/24
172.21.4.0/24
```

### Автосуммирование

Автоматическое суммирование на границах классовых сетей.

```cisco
router rip
 no auto-summary    ! Отключить (обычно нужно!)
```

## Полезные команды

### OSPF

```cisco
show ip ospf neighbor              ! Соседи OSPF
show ip ospf interface brief       ! Интерфейсы в OSPF
show ip ospf database              ! База данных LSA
show ip route ospf                 ! Только OSPF-маршруты
```

### BGP

```cisco
show ip bgp summary                ! Соседи BGP
show ip bgp                        ! Таблица BGP
show ip bgp neighbors              ! Детали соседства
show ip route bgp                  ! Только BGP-маршруты
```

### Общие

```cisco
show ip route                      ! Вся таблица маршрутизации
show ip protocols                  ! Активные протоколы
show running-config | section ospf ! Конфигурация OSPF
show running-config | section bgp  ! Конфигурация BGP
```

## Чтение таблицы маршрутизации

```
O E2  172.22.10.0/24 [110/20] via 172.21.12.1, 00:05:32, Fa0/0
│ │        │           │  │         │            │         │
│ │        │           │  │         │            │         └─ Интерфейс
│ │        │           │  │         │            └─ Время жизни
│ │        │           │  │         └─ Next-hop (следующий роутер)
│ │        │           │  └─ Метрика
│ │        │           └─ AD (административное расстояние)
│ │        └─ Сеть назначения
│ └─ E2 = OSPF External Type 2
└─ O = OSPF
```

### Коды маршрутов

| Код | Источник |
|-----|----------|
| C | Connected (прямое подключение) |
| S | Static |
| O | OSPF |
| O E2 | OSPF External Type 2 |
| B | BGP |
| R | RIP |

## Контрольные вопросы

### 1. Что такое административное расстояние?

Числовое значение (0-255), определяющее приоритет источника маршрута. Меньше = надёжнее. Используется при выборе между маршрутами от разных протоколов.

### 2. Различие классовых и бесклассовых протоколов?

- **Классовые** (RIPv1): НЕ передают маску, предполагают классовую (A/B/C)
- **Бесклассовые** (RIPv2, OSPF, BGP): Передают маску, поддерживают VLSM

### 3. Максимум роутеров в RIPv2?

**15 роутеров** (метрика 16 = недостижимо).

## Частые ошибки

### OSPF соседство не устанавливается

- Проверить: интерфейсы в одной подсети?
- Проверить: area совпадает?
- Проверить: Hello/Dead интервалы одинаковые?
- Проверить: `no shutdown` на интерфейсах?

### BGP соседство не устанавливается

- Проверить: `neighbor` IP правильный?
- Проверить: `remote-as` правильный?
- Проверить: TCP-связность (ping)?
- Проверить: нет ли ACL, блокирующего порт 179?

### Маршруты не перераспределяются

- В OSPF: добавить `subnets` к `redistribute`
- Проверить: сеть существует в таблице маршрутизации?
