## Основные понятия

### TCP vs UDP

| Протокол | Особенности | Примеры использования |
|----------|-------------|----------------------|
| **TCP** | Надёжный, с установкой соединения, гарантия доставки | FTP, HTTP, SSH |
| **UDP** | Быстрый, без соединения, нет гарантии доставки | DHCP, DNS, видеозвонки |

### Порты

- **Порт** — номер приложения на компьютере (как номер квартиры в доме)
- IP-адрес указывает компьютер, порт указывает конкретный сервис
- Диапазон: 0-65535 (0-1023 — стандартные сервисы)

### Основные порты

| Порт | Протокол | Сервис |
|------|----------|--------|
| 20 | TCP | FTP (данные) |
| 21 | TCP | FTP (управление) |
| 67 | UDP | DHCP (сервер, bootps) |
| 68 | UDP | DHCP (клиент, bootpc) |
| 80 | TCP | HTTP |

## DHCP

### Что делает
Автоматически выдаёт IP-адреса, маску, шлюз, DNS клиентам.

### Процесс DORA

```
PC (0.0.0.0)                    DHCP-сервер
    │                               │
    │ ── 1. DISCOVER (broadcast) ─→ │  "Кто выдаёт IP?"
    │ ←── 2. OFFER ──────────────── │  "Предлагаю 172.17.71.10"
    │ ── 3. REQUEST (broadcast) ──→ │  "Хочу этот адрес"
    │ ←── 4. ACK ───────────────── │  "Готово, он твой"
```

### Проблема: DHCP через роутер

Broadcast не проходит через маршрутизатор (по замыслу — иначе сеть захлебнётся).

**Решение — ip helper-address:**

```
interface FastEthernet1/1.71
 ip helper-address 172.17.0.2
```

Роутер перехватывает DHCP broadcast и пересылает unicast'ом на указанный адрес. Добавляет поле **giaddr** (IP интерфейса роутера), чтобы сервер знал, из какой подсети запрос.

### Конфигурация DHCP-сервера

```
ip dhcp excluded-address 172.17.71.1    ! Не выдавать адрес шлюза

ip dhcp pool VLAN71
 network 172.17.71.0 255.255.255.0      ! Пул адресов
 default-router 172.17.71.1              ! Шлюз для клиентов
```

## VLAN и субинтерфейсы

### Router-on-a-Stick

Один физический порт обрабатывает несколько VLAN через тегирование 802.1Q.

```
Fa1/1 (физический) ─┬─ Fa1/1.71 (VLAN 71) → 172.17.71.0/24
                    └─ Fa1/1.17 (VLAN 17) → 172.17.17.0/24
```

### Настройка субинтерфейса

```
interface FastEthernet1/1.71
 encapsulation dot1Q 71              ! Обрабатывать кадры с тегом VLAN 71
 ip address 172.17.71.1 255.255.255.0
```

### VTP (VLAN Trunking Protocol)

- Автоматически распространяет список VLAN между коммутаторами
- **НЕ назначает** порты в VLAN — это делается вручную
- Режимы: Server, Client, Transparent
- Не путать с STP/PVST (защита от петель)

## ICMP и ping

### ICMP работает поверх IPv4

```
┌─────────────────────┐
│ IPv4-заголовок      │
│ protocol: 1 (ICMP)  │
├─────────────────────┤
│ ICMP-сообщение      │
│ type: 8 или 0       │
└─────────────────────┘
```

### Типы ICMP

| Type | Название | Описание |
|------|----------|----------|
| 0 | Echo Reply | Ответ на ping |
| 8 | Echo Request | Запрос ping |

### Как работает ping

```
PC1 ── Echo Request (type 8) ──→ PC2
PC1 ←── Echo Reply (type 0) ──── PC2
```

## ACL (Access Control Lists)

### Типы ACL

| Тип | Номера | Критерии фильтрации |
|-----|--------|---------------------|
| Стандартный | 1-99, 1300-1999 | Только IP источника |
| Расширенный | 100-199, 2000-2699 | IP источника/назначения, протокол, порты |

### Направление применения

| Направление | Когда проверяется | Рекомендация |
|-------------|-------------------|--------------|
| **in** | При входе на интерфейс | Ближе к источнику — экономит ресурсы |
| **out** | При выходе с интерфейса | Ближе к назначению |

### Важно помнить

- В конце каждого ACL неявное `deny any` (отбрасывает всё, что не разрешено)
- Правила проверяются **по порядку** сверху вниз
- Первое совпадение — применяется, остальные не проверяются

## Настроенные ACL в лабораторной

### 1. Блокировка FTP для PC1, PC2, PC3

```
ip access-list extended BLOCK_FTP_FROM_VLAN71
 deny tcp 172.17.71.0 0.0.0.255 any eq ftp    ! Порт 21
 deny tcp 172.17.71.0 0.0.0.255 any eq 20     ! Порт 20
 permit ip any any

interface FastEthernet1/1.71
 ip access-group BLOCK_FTP_FROM_VLAN71 in
```

### 2. Блокировка DHCP для PC6

```
ip access-list extended DENY_DHCP
 deny udp any any eq bootpc                    ! Порт 68
 deny udp any any eq bootps                    ! Порт 67
 permit ip any any

interface FastEthernet0/1.71
 ip access-group DENY_DHCP in
```

**Результат:** PC6 не может получить IP по DHCP.

### 3. Блокировка исходящего ping для PC7

```
ip access-list extended BLOCK_ECHO
 deny icmp 172.17.18.0 0.0.0.255 any echo     ! Запретить echo request
 permit icmp any any echo-reply                ! Разрешить echo reply
 permit ip any any

interface FastEthernet0/1.17
 ip access-group BLOCK_ECHO in
```

**Результат:**
- PC7 пингует PC1 → ❌ не работает (request блокируется)
- PC1 пингует PC7 → ✅ работает (reply разрешён)
